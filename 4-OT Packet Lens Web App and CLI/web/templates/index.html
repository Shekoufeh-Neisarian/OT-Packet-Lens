Analysis methodology and interpretation limits

Observed: packet bytes, timestamps, reported IP addresses, transport ports and captured-frame lengths. A claimed identity is not authenticated.

Derived: TShark protocol dissections, rates, function-code occurrences and MAC/OUI lookup. Wireshark display-filter counts can overlap. In particular, inner UDP headers inside ICMP error packets also satisfy the udp display filter, while outer transport totals count only the outer protocol.

Inferred: suspected PLC/HMI/EWS roles, scan hypotheses, alert severity and write success. These need operational confirmation; never treat them as proven incidents or physical identities.

Decoding audit TShark frame and field provenance

TShark protocol-stack presence: each value counts frames whose decoded frame.protocols contains that protocol (use independent -Y validation for exact GUI-filter parity), not necessarily distinct messages. A frame may match both tcp and modbus.
